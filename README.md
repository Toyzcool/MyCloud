# MyCloud

> 把 Mac 上的文件夹自动、单向地备份到局域网里的 SMB 硬盘（路由器 USB 硬盘、NAS），体验接近 iCloud：登录后在后台运行，文件一变就同步。
> 零第三方依赖：只用 macOS 自带的 `python3`、`rsync`、`mount_smbfs`。
>
> 下载：[Releases](https://github.com/Toyzcool/MyCloud/releases) · 许可证：[MIT](LICENSE)

## 1. 先读：它是什么，不是什么

MyCloud 在你登录 Mac 后自动运行，把你指定的文件夹（或单个文件）单向镜像到 SMB 共享上，并在文件变化后自动增量同步。

> ### ⚠️ 这是「单副本便利镜像」，不是「3-2-1 备份」
>
> 1. **NAS 上只有一份副本。** 那块硬盘坏了、被格式化或丢了，这份副本就没了。MyCloud 不做异地副本，也不做长期多版本归档。
> 2. **回收站会被定期清理。** 被覆盖的旧版本和被删除的文件，会先移进 NAS 上的回收站 `.trash/<时间戳>/`，超过保留期（默认 30 天）或容量上限（默认 50 GB）后**永久删除**。
> 3. **删除会同步过去。** 你在本机删掉的文件，NAS 镜像里也会移走（进回收站）。这是"镜像"的含义，不是 bug。
>
> 把它当作"NAS 上随时有一份和电脑几乎一样的拷贝"，用于换机、找回误删、临时取用。真正重要、不可再生的数据，请另外做 Time Machine 和异地/云端备份。

**单向**的意思是：只从 Mac 复制到 NAS，绝不反向写回你的 Mac；NAS 上的改动不会同步回来。

## 2. 系统要求

| 项目 | 要求 |
|---|---|
| macOS | 12 Monterey 或更新；Intel 与 Apple 芯片通用 |
| 命令行工具 | Xcode Command Line Tools（提供 `/usr/bin/python3` 与 `/usr/bin/rsync`）。没装的话，安装向导里点一下就能装 |
| 存储端 | 同一局域网内任意 SMB 共享：路由器 USB 硬盘、群晖/威联通 NAS、另一台 Mac 的文件共享等。支持用户名密码登录，也支持匿名（guest） |
| 授权 | 给 `/usr/bin/python3` 授予「完全磁盘访问权限」（见 [4.4](#44-授予完全磁盘访问权限必做)）；较新的 macOS 上可能还要允许「本地网络」 |

不需要、也不要安装 Homebrew、pip 包或其他同步工具。MyCloud 固定使用系统自带的 `/usr/bin/python3`。

## 3. 快速开始

1. 从 [Releases](https://github.com/Toyzcool/MyCloud/releases) 下载最新的 `MyCloud-x.y.z.zip`，解压后把 **MyCloud.app** 拖到「应用程序」。
2. 首次打开：macOS 12–14 **右键 → 打开**；macOS 15 及以后双击一次后，到 **系统设置 → 隐私与安全性** 点「**仍要打开**」（详见 [4.2](#42-首次打开)）。
3. 按安装向导完成三步：**环境 → 云盘连接 → 备份内容**，点「安装并启动」。
4. 按概览页提示，给 `/usr/bin/python3` 授予「完全磁盘访问权限」，然后点「重启守护进程」。
5. 菜单栏图标变成对勾（✓☁︎）即表示已在同步。之后无需任何操作。

## 4. 安装详解

### 4.1 下载

到 [Releases](https://github.com/Toyzcool/MyCloud/releases) 下载最新版本的 `MyCloud-x.y.z.zip`，解压得到 `MyCloud.app`，拖进「应用程序」文件夹。

应用包里自带后台守护进程和全部模板，不需要克隆仓库，也不需要打开终端。

### 4.2 首次打开

MyCloud 是自签名应用，没有经过 Apple 公证，所以第一次打开时 Gatekeeper 会拦截。这是预期的，不代表文件损坏。

- **macOS 12–14**：在「应用程序」里**右键 MyCloud → 打开**，在弹窗里再点「打开」。
- **macOS 15 及以后**：先双击打开一次（会被拦下），然后打开 **系统设置 → 隐私与安全性**，在页面底部找到关于 MyCloud 的提示，点「**仍要打开**」，输入登录密码确认。

只有第一次需要这样做。应用常驻菜单栏，关闭窗口不会退出。

### 4.3 安装向导

没有安装过的 Mac 会看到「欢迎使用 MyCloud」安装向导：

**1 · 环境**：检查命令行工具是否已安装。缺失时点「安装命令行工具…」，系统会弹出安装对话框，装完后点「重新检查」。

**2 · 云盘连接**：填写 SMB 服务器地址（IP 或主机名）、共享名，选择连接方式：
- **注册用户（用户名 + 密码）**：密码只用于这一步验证，验证通过后才保存到登录钥匙串和 `~/Library/Preferences/nsmb.conf`（权限 600）。
- **匿名（guest，无需密码）**：存储端需要允许 guest 访问该共享。

向导会用临时挂载点实测连接。共享上如果已经有另一台 Mac 的 MyCloud 备份，会提示你确认是否「接管」（同一个 NAS 目录同一时间只能有一台 Mac 在写，见 [13](#13-常开的备份网关机)）。

**3 · 备份内容**：点「添加文件夹…」选择要备份的文件夹，至少一个。之后可以随时在「同步项」页增减，也可以添加单个文件。

点「**安装并启动**」，通常 1–2 分钟完成：安装后台守护进程（`~/Library/Application Support/MyCloud/`），注册开机自启（LaunchAgent），并开始首次同步。

### 4.4 授予「完全磁盘访问权限」（必做）

后台守护进程要读取 `~/Documents`、`~/Desktop`、iCloud 云盘等受系统保护的位置，必须授权。**授权对象是 `/usr/bin/python3`，不是 MyCloud.app。**

安装完成后，概览页会出现授权提示，按钮可以直达设置：

1. 点「打开「完全磁盘访问」设置」。
2. 点「在访达中显示 python3」，把 `python3` 拖进权限列表（或点列表下方的 `+`，按 `⌘⇧G` 输入 `/usr/bin/python3`）。
3. 确认它的开关已打开。
4. 回到 MyCloud，点「重启守护进程」。

> **注意范围**：这个授权对本机上所有用 `/usr/bin/python3` 运行的脚本都生效。这是"零依赖、免编译"换来的代价，请自行评估。

### 4.5 「本地网络」权限

较新的 macOS 可能会拦截后台进程访问局域网设备，症状和"NAS 掉线"一模一样。如果一直连不上 NAS，到 **系统设置 → 隐私与安全性 → 本地网络**，确认与 MyCloud / python3 相关的条目已打开。

### 4.6 命令行安装（可选）

适合脚本化部署，效果与图形向导相同：

```bash
git clone https://github.com/Toyzcool/MyCloud.git ~/src/MyCloud
```

```bash
cd ~/src/MyCloud && bash install/install.sh
```

不要用 `sudo`。安装器会交互询问服务器、共享、连接方式和密码（不回显，只经标准输入传递）。命令行安装只装后台守护进程；图形界面仍需从 Releases 下载 MyCloud.app。

## 5. 使用应用

### 5.1 菜单栏图标

| 图标 | 含义 |
|---|---|
| ✓ 云朵带对勾 | 空闲，一切正常 |
| ↻ 云朵带箭头 | 正在同步，或守护进程正在启动/重启 |
| ! 云朵带感叹号 | 需要你处理：有待确认的删除、多次失败的文件、上次同步报错、守护进程无响应等 |
| ⊘ 云朵带斜杠 | 离线（连不上 NAS）、已暂停或已停止 |

点击图标弹出小窗：当前状态、进度、「立即同步」「打开 MyCloud」「退出」。退出只关闭界面，**后台备份继续运行**。

### 5.2 概览

- **状态**：空闲 / 同步中 / 离线 / 需要处理 / 同步停滞 / 守护进程无响应 等，以及「上次成功同步」时间。上次同步出错时，原因直接显示在这里。
- **进度**：正在扫描、计算变更、上传（"备份中 120/800 文件 · 第 2/5 批"）、从 iCloud 下载等，以及最近一次传输的时间。
- **操作**：「立即同步」「暂停」「恢复」；守护进程异常时出现「重启守护进程」「打开日志文件夹」。
- **最近活动**：每轮同步复制、归档了多少文件。

### 5.3 同步项

列出所有备份源（文件夹或单个文件），右上角「添加文件」「添加文件夹」，每项可以移除。

- 移除一个同步项后，NAS 上它的旧镜像**原样保留**，在「问题」页标为「孤立目录」，不会被自动删除，需要的话请自己在访达里清理。
- 同名文件夹（例如两个 `Projects`）会自动加 `-2`、`-3` 后缀区分。
- 「目标目录」可以修改备份落在共享里的哪个目录（默认 `MyCloud`），也可以「浏览 NAS 选择目录…」。

### 5.4 问题

所有需要你知道或处理的事都汇总在这里；没有问题时显示「一切正常，暂无待处理问题」。

| 分区 | 含义与处理 |
|---|---|
| **待确认删除** | 一次要删的文件太多，被保护机制拦下（见 [9](#9-删除保护)）。核对清单无误后点「批准全部删除」；不是你的本意就不要批准，先查明原因 |
| **永久失败清单** | 连续多轮都没能传上去的文件。每轮仍会重试，成功或本机删除后自动移出。常见原因与处理见 [14.3](#143-永久失败清单) |
| **仅存于 iCloud 云端、未包含在备份** | 文件只在 iCloud 云端、本机没有内容，所以备份不到。点「立即下载到本机」，下载后会自动备份（见 [7](#7-用-icloud-云盘作为备份源)） |
| **暂缓的删除** | 本机已不存在、但可能只是被移动了的仅云端文件，NAS 副本暂时保留，文件下载回本机并备份后会正常处理 |
| **孤立目录** | 已从同步项移除的源，在 NAS 上留下的旧镜像 |
| **最近错误** | 守护进程报告的最近一次错误 |
| **深度校验** | 最近一次深度校验（逐个核对 NAS 上的文件）的结果 |
| **诊断** | 点「运行诊断」逐项检查：网络、挂载、权限、rsync 能力、目标可写、电源设置等，失败项附处理建议，部分可一键修复 |

### 5.5 设置

| 分区 | 内容 |
|---|---|
| **云盘连接** | 修改服务器、共享、连接方式、用户名和密码，点「测试并保存」：先实测，通过后才保存并重启守护进程 |
| **回收站与阈值** | 回收站保留天数、容量上限；删除保护的数量与比例阈值 |
| **扫描与监视** | 变更检测方式（自动 / kqueue / 定时扫描）与扫描间隔 |
| **iCloud 云端文件** | 对仅云端文件「跳过」或「下载后备份」；「备份后自动释放本地空间」 |
| **立即校验备份** | 触发一次深度校验 |
| **守护进程** | 安装状态、后端版本；「更新后端」（升级后必点，见 [12](#12-升级)）；「打开日志文件夹」；「卸载 MyCloud 守护进程…」 |

## 6. 同步是怎么进行的

- **何时同步**
  - 文件变化后几秒内（kqueue 近实时监视；目录太多时自动改为定时扫描，默认每 30 秒）。
  - 每 15 分钟一次全量核对，兜底捕捉监视漏掉的修改（如数据库、日志文件的原地写入）。
  - Mac 从睡眠中唤醒后、点「立即同步」时。
  - 每周一次深度校验：逐个核对 NAS 上的文件，缺失或不一致的自动排队重传。
- **怎么同步**：本地用 SQLite 清单记录每个文件的大小和修改时间，每轮只比对本机，不扫描 NAS；新增和修改的文件分批用 rsync 上传，上传成功并核对后才记入清单，中途断电或断网下次从断点继续。被覆盖的旧版本和被删除的文件进 NAS 回收站。
- **断网与 NAS 离线**：自动卸载、退避重连，恢复后继续；NAS 长时间离线（默认 24 小时）才通知一次，避免开机时 NAS 还没上线的噪音。
- **出错时**：只有挂载出了问题（传输被中断、超时、NAS 不响应）才重新挂载；其他错误保留挂载，原因显示在概览页，按 5 分钟、10 分钟……最长 1 小时的间隔重试，不会反复掉线重连。
- **睡眠**：同步进行中会阻止 Mac 空闲睡眠；Mac 睡着后不会同步，醒来后自动补上。
- **首次同步**：文件多时（几十万个、几百 GB）要几个小时甚至更久，期间可以正常使用电脑。

## 7. 用 iCloud 云盘作为备份源

可以把 iCloud 云盘（`~/Library/Mobile Documents/com~apple~CloudDocs`）添加为同步项，把 iCloud 里的文件备份到 NAS。

**关键：关闭「优化 Mac 储存空间」。** 开着它时，macOS 会把不常用的文件移出本机，只留在 iCloud 云端，而后台进程通常无法触发下载，这些文件就备份不到。
- macOS 12：系统偏好设置 → Apple ID → iCloud → 取消勾选「优化 Mac 储存空间」
- macOS 13 及以后：系统设置 → Apple ID → iCloud → iCloud 云盘 → 关闭「优化 Mac 储存空间」

**仅云端的文件**会列在「问题」页。两种处理方式：
- 点「立即下载到本机」：由应用在前台下载，下载后守护进程自动备份。
- 「设置 → iCloud 云端文件」改为「下载后备份」，并可开启「备份后自动释放本地空间」。

**移出本地不等于删除。** 一个已经备份过的文件被移出本机后，MyCloud 不会删除它在 NAS 上的副本；在访达里移动、改名这类文件，也会尽量在 NAS 上同步改名，确认不了的就暂缓删除（「暂缓的删除」）。macOS 12/13 上被移出的文件是隐藏的 `.文件名.icloud` 占位文件，MyCloud 能识别它们。

## 8. NAS 上的目录结构与恢复文件

恢复**不需要 MyCloud**，在访达里就能完成。访达 → 前往 → 连接服务器（`⌘K`），输入 `smb://<NAS地址>/<共享名>`：

```
<共享>/
├── .mycloud_sentinel          ← 挂载身份标记（请勿删除）
└── MyCloud/                   ← 目标目录（可在「同步项 → 目标目录」修改）
    ├── data/                  ← 当前镜像，和你电脑上的一样
    │   ├── Documents/
    │   └── Desktop/
    ├── .trash/                ← 旧版本与被删除的文件，按时间分批
    │   ├── 2026-10-01T031500/
    │   └── 2026-10-04T153000/
    └── last_sync.json         ← 最近一次成功同步的时间
```

- **恢复当前文件**：从 `MyCloud/data/<同步项>/` 拷回本机。
- **恢复被删除或被覆盖前的版本**：到 `MyCloud/.trash/`，批次目录名是 **UTC 时间**（`2026-10-04T153000` = UTC 2026-10-04 15:30:00，比北京时间晚 8 小时），里面按原路径存放那一轮被覆盖或删除的文件。

> ⏳ 回收站里超过保留期（默认 30 天）或超出容量上限（默认 50 GB）的批次会被永久清理，需要的文件请尽早取回。

> `.trash` 等以点开头的目录在访达里默认隐藏，按 `⌘⇧.` 显示。

## 9. 删除保护

MyCloud 有多层保护，防止"本地误删一大批文件，同步后 NAS 也跟着清空"：

- **删除都是进回收站**，不会直接销毁；只有回收站过期清理会真正删除数据，而且只在一切正常、没有被拦下的删除时才执行。
- **大规模删除拦截**：某个同步项一轮要删除的文件超过 **200 个**或超过镜像的 **20%**，删除会被拦下（新文件照常同步），状态显示「待确认删除」，并每天提醒一次。到「问题」页核对后点「批准全部删除」才放行。如果不是你的本意（例如外接硬盘没插，源文件夹"看起来空了"），**不要批准**。
- **源消失保护**：源文件夹不见了、或所在磁盘被卸载换成了空目录，整个同步项跳过，不会清空镜像。
- **扫描出错保护**：某一轮扫描本机时有目录读取失败，本轮暂不执行任何删除。
- **仅云端文件保护**：见 [7](#7-用-icloud-云盘作为备份源)。
- **能力自检**：每次启动检测本机 rsync 的行为，一旦和预期不符（例如系统更新改了 rsync），自动停用删除同步、只保留复制，并在「问题」页提示。

## 10. 命令行 mycloudctl

所有操作都能在应用里完成；命令行适合远程登录、写脚本或排查问题。它就是守护进程目录里的一个脚本：

```bash
/usr/bin/python3 ~/Library/Application\ Support/MyCloud/mycloudctl.py status
```

用命令行安装器安装时，会尽量创建 `/usr/local/bin/mycloudctl` 快捷方式（该目录可写时），之后可以直接写 `mycloudctl status`。也可以自己加个别名：

```bash
echo "alias mycloudctl='/usr/bin/python3 \"\$HOME/Library/Application Support/MyCloud/mycloudctl.py\"'" >> ~/.zshrc
```

| 命令 | 作用 |
|---|---|
| `status` | 总体状态、上次成功时间、各同步项进度、待确认删除、永久失败清单（`--json` 输出机器可读格式） |
| `sync-now` | 立即同步 |
| `pause` / `resume` | 暂停 / 恢复后台同步 |
| `reload` | 重新读取 `config.ini` |
| `verify` | 深度校验：逐个核对 NAS 上的文件并输出结果 |
| `approve-deletions` | 放行被拦下的大规模删除 |
| `doctor` | 逐项诊断（`--json` 可选） |
| `logs` | 显示日志路径和最近的日志（`-f` 持续跟随） |
| `materialize` | 下载仅云端的 iCloud 文件，以便备份（`--dry-run` 只统计） |
| `config-get` | 以 JSON 输出当前配置 |
| `config-add-source` / `config-remove-source` | 增删同步项 |
| `config-set <键> <值>` | 修改一个数值类设置（见 [11](#11-配置文件-configini)） |
| `config-set-dest` | 修改目标目录 |
| `server-set` | 修改 NAS 连接（密码用 `--password-stdin` 从标准输入读入，绝不放在命令行上） |
| `version` | 后端版本 |
| `uninstall` | 卸载守护进程（不动 NAS 上的数据） |

## 11. 配置文件 config.ini

配置文件位于 `~/Library/Application Support/MyCloud/config.ini`。一般用应用的「设置」修改即可；手工编辑后执行 `mycloudctl reload` 生效。

```ini
[server]
host = 192.168.1.10          ; NAS 的 IP 或主机名
share = SHARE                ; 共享名
username = user              ; 用户名（匿名模式下不用）
; 密码不在这里：保存在登录钥匙串与 ~/Library/Preferences/nsmb.conf（600）
; sentinel_uuid 由安装器生成，请勿手改

[backup]
folders =                    ; 要备份的文件夹或文件，每行一个，支持 ~
    ~/Documents
    ~/Desktop
exclude =                    ; 额外的排除规则，每行一个，匹配文件名或文件夹名
    *.photoslibrary
dest_rel = MyCloud           ; 备份落在共享里的哪个目录
retention_days = 30          ; 回收站保留天数
trash_max_gb = 50            ; 回收站容量上限（GB）
max_delete_files = 200       ; 一轮删除超过这么多文件就拦下
max_delete_pct = 20          ; 或超过镜像的这个百分比
hot_interval = 30            ; 定时扫描间隔（秒）
full_interval = 900          ; 全量核对间隔（秒）
watch_mode = auto            ; auto | kqueue | scan
offline_notify_hours = 24    ; NAS 离线多久才通知
icloud_policy = skip         ; skip（跳过仅云端文件） | download（下载后备份）
icloud_evict_after_backup = true
upload_concurrency = 4       ; 并行上传的 rsync 进程数（1–16）
rsync_inplace = true         ; 新文件直接写入（更快）
rsync_no_times = true        ; 不在 NAS 上保留修改时间（更快；备份的真实信息在本地清单）
```

**排除规则**按文件名或文件夹名匹配（通配符 `*`、`?`），写完整路径不会生效。以下内容总是被排除：

```
.DS_Store  .Trashes  .TemporaryItems  .localized  ._*  *.tmp  ~$*
node_modules  .git  __pycache__  *.pyc  .venv  .pytest_cache  .mypy_cache  .tox  .ruff_cache
```

被排除的文件，NAS 上已有的副本会保留，不会被删除。

## 12. 升级

1. 从 [Releases](https://github.com/Toyzcool/MyCloud/releases) 下载新版 zip。
2. 点菜单栏图标 →「退出」（后台备份不受影响）。
3. 解压，把 MyCloud.app 拖进「应用程序」并替换。首次打开同 [4.2](#42-首次打开)。
4. **进入「设置 → 守护进程」，点「更新后端」。** 大部分修复都在后台守护进程里，不做这一步就等于没升级。它只替换程序文件并重启守护进程，连接设置、同步项和同步记录都不变。

确认版本：

```bash
/usr/bin/python3 ~/Library/Application\ Support/MyCloud/mycloudctl.py version
```

也可以用 git 只升级后台守护进程（把仓库 clone 在 iCloud 云盘以外，例如 `~/src/MyCloud`）：

```bash
cd ~/src/MyCloud && git fetch --tags && git checkout vX.Y.Z && bash install/install.sh --refresh
```

> 用 git 把后端升级到较新版本后，**不要在旧版应用里点「重新安装后端文件」**，那会把应用内置的旧后端装回去。

## 13. 常开的备份网关机

如果要让一台常开的 Mac（例如旧笔记本）专门负责把 iCloud 云盘备份到 NAS，请参考 [deploy/DEPLOY-GATEWAY.md](deploy/DEPLOY-GATEWAY.md)，要点：

- **单写者**：同一个 NAS 目录同一时间只能有一台 Mac 的 MyCloud 在写，否则两台会把对方传的文件当作"多余"归档。换机时先在旧机暂停，新机接管成功后再卸载旧机。
- **防睡眠**：系统设置里允许接电源时显示器关闭后不睡眠；空闲时睡着的网关不会发现新文件。
- **自动登录**：守护进程只在有用户登录的图形会话里运行，停电重启后停在登录窗口就不会恢复备份。
- **关闭「优化 Mac 储存空间」**，等 iCloud 全部下载完成再装 MyCloud。
- 可以迁移旧机的本地清单，免去几十 GB 的重新上传（指南第 4 节）。

## 14. 故障排查

先到「问题 → 运行诊断」，或运行 `mycloudctl doctor`，大多数问题会直接给出原因和处理建议。

### 14.1 状态含义

| 状态 | 含义 | 处理 |
|---|---|---|
| 空闲 | 正常 | — |
| 同步中 / 启动中 | 正常 | — |
| 离线 | 连不上 NAS | 检查 NAS 是否开机、是否在同一网络、「本地网络」权限；恢复后会自动重连 |
| 需要处理 | 有待确认删除、多次失败的文件或最近错误 | 到「问题」页查看 |
| 待确认删除 | 大规模删除被拦下 | 见 [9](#9-删除保护) |
| 同步停滞 | 正在传输但长时间没有进展 | 通常会自动恢复；持续出现时点「重启守护进程」并查看日志 |
| 守护进程无响应 / 已退出 | 后台进程卡住或退出 | 点「重启守护进程」；反复出现请查看日志 |
| 已暂停 / 已停止 | 你暂停了，或守护进程被停止 | 点「恢复」 |

### 14.2 常见问题

**装好后一直显示「离线」**
- 最常见：还没给 `/usr/bin/python3` 授予完全磁盘访问权限（见 [4.4](#44-授予完全磁盘访问权限必做)），授权后点「重启守护进程」。
- 「本地网络」权限被拦截（见 [4.5](#45-本地网络权限)）。
- NAS 地址、共享名、密码不对：到「设置 → 云盘连接」重新「测试并保存」。

**某些文件没有备份**
- 在排除规则里（见 [11](#11-配置文件-configini)）。
- 只在 iCloud 云端（「问题」页「仅存于 iCloud 云端」）。
- 在「永久失败清单」里（见下）。

**提示「路由器接受了登录，但拒绝连接共享」**：登录成功了，但共享不可用，通常是路由器上的 USB 硬盘没挂载（例如断电重启后）、共享名已不存在或权限变了。到路由器管理页检查 USB 存储；恢复后会自动重连。

**提示「本机的 rsync 不接受 MyCloud 的上传命令」**：本机 rsync 与当前版本不兼容。到「设置 → 守护进程」点「更新后端」，并查看日志。

**macOS 大版本升级后备份停了**：升级常会让命令行工具失效，守护进程起不来。MyCloud 有一个独立的看门狗，状态超过 48 小时没更新会单独通知你。重新安装命令行工具：

```bash
xcode-select --install
```

装完后在应用里点「重启守护进程」。

### 14.3 永久失败清单

连续多轮都没能上传的文件会列在这里，每轮仍会重试，上传成功或本机删除后自动移出。常见原因：

| 原因 | 处理 |
|---|---|
| 文件名含 SMB/exFAT 不允许的字符 `\ : * ? " < > \|`，或以点、空格结尾，或名字超过 255 字节 | 改名。访达里显示的 `/` 在系统里是 `:` |
| 单个文件超过 4 GB，而 NAS 硬盘是 FAT32 | 把硬盘换成 exFAT 等格式，或排除该文件 |
| 失效的符号链接 | macOS 12–14 自带的 rsync 会把它作为链接本身备份；macOS 15+ 的 openrsync 不支持，会一直列在这里。删掉或修好链接即可 |
| 正在被应用持续写入的文件（数据库、缓存） | 是缓存就加入排除规则；是重要数据就等应用关闭后同步 |
| 本机没有读取权限 | 检查完全磁盘访问权限 |

### 14.4 日志与状态文件

| 位置 | 内容 |
|---|---|
| `~/Library/Logs/MyCloud/mycloud.log` | 守护进程日志（滚动保留） |
| `~/Library/Application Support/MyCloud/runtime/state.json` | 当前状态 |
| `~/Library/Application Support/MyCloud/runtime/journal.ndjson` | 每轮同步的流水 |
| `~/Library/Application Support/MyCloud/runtime/manifest.db` | 本地文件清单 |

## 15. 卸载

在「设置 → 守护进程」点「卸载 MyCloud 守护进程…」，或运行：

```bash
/usr/bin/python3 ~/Library/Application\ Support/MyCloud/mycloudctl.py uninstall --yes
```

卸载会停止并移除后台守护进程和开机自启项，删除本地运行目录（配置和日志默认先备份到 `~/Library/Application Support/MyCloud.bak-日期`，加 `--no-backup` 不备份）；`--remove-keychain`、`--strip-nsmb` 可同时清除钥匙串和 nsmb.conf 里保存的密码。然后把 MyCloud.app 拖到废纸篓即可。

> ✅ **卸载不会碰 NAS 上的任何数据。** 镜像（`data/`）和回收站（`.trash/`）都原样保留，随时可以在访达里取用；要彻底清理，请手动删除共享上的 `MyCloud/` 目录。

## 16. 安全与隐私

- **不联网**：除了你配置的 SMB 共享，MyCloud 不连接任何服务器，不收集任何数据，没有自动更新检查。
- **密码**：只在验证连接成功后，保存到登录钥匙串与 `~/Library/Preferences/nsmb.conf`（权限 600）；从界面到后台全程经标准输入传递，不写进配置文件和日志。已知限制：macOS 12 上挂载时会把密码放进 `mount_smbfs` 的启动参数，挂载的几秒内本机其他进程可以从进程列表看到它。
- **只读你的源文件**：绝不向本机写入或修改你的文件；挂载点未挂载时设为只读（0500），防止误把数据写到本机。
- **授权范围**：完全磁盘访问授予的是 `/usr/bin/python3`，见 [4.4](#44-授予完全磁盘访问权限必做)。
- **不用 sudo**：安装、运行、卸载都在你自己的用户下完成。
- 请不要使用路由器出厂的弱口令保护共享。
